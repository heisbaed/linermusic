# Cine music 0.1.16

Version code 19. Separate Mobile and TV APKs; existing account/install identity retained.

- TV Home: horizontal top navigation replaces the left rail, using Spotify's published TV layout as reference. A personalized artwork feature, For you / New releases / Recent views, compact library shortcuts, music shelves and a restrained Dj Cine entry use actual catalog/library data. New releases retain the 30-day date check. Shared card, list, heading and action sizes are reduced across browsing, details, search and settings. Mobile lists, library destinations, shelves, detail covers and profile/settings elements share a more compact scale without reducing 48 dp actions.
- TV listening: full-screen artwork remains. The short, unboxed transport sits at bottom left; title/artist stay below it at bottom left. Header/transport hide after five idle seconds without moving the title. Native remote input or pointer input reveals controls; the first directional/Select press restores focus rather than activating an invisible control. Media transport keys still perform their actions. Lyrics and Up Next use open split layouts with album/artist artwork on the left and lyrics/queue on the right, over a blurred artwork-derived background. Now Playing is separated from upcoming songs. Buttons are 48 dp, with a slightly larger 56 dp Play/Pause control.
- Artwork: TV requests larger provider cover variants, enriches visible video-frame/missing covers from the exact album or known main artist, and falls back to a branded placeholder when no suitable image is available. Small decoded images and failed images trigger artist fallback. Resolved addresses persist in a bounded metadata cache; image files retain the existing native disk cache. This is not automatic restoration of blurry originals: source artwork availability still limits quality. Original emblem geometry is used for in-app branding.
- Playback: next-song buffering is independent of the Gapless/Crossfade setting. Preparation starts after the active stream settles and has buffer available, rather than waiting for its final 25 seconds. A ready next player is reused on manual Next and natural completion. The next two following source addresses are warmed with bounded background work; audio buffering remains limited to one next player. Queue/context/quality changes cancel stale preparation; queue appends that preserve the selected next song retain its buffer. A failed warm-up has one delayed retry and normal playback recovery remains available. Network/provider conditions can still cause buffering, especially during skips faster than preparation.
- Appearance: each app theme has a matching crisp launcher icon and vector in-app emblem. Selecting an icon changes its corresponding theme and changing a theme changes the icon. Pink glass, Dark green, Smoke white and Dark palettes are available on TV as well as mobile. TV launcher banners also have matching variants. Launcher refresh timing depends on the device.
- Dj Cine: requests in English/Kiswahili, Familiar/Balanced/Discover choices, real catalog song selection, optional Gemini planning/curation through Firebase AI Logic, music-only fallback, voice requests where the OS supports them, optional introductions using installed offline device voices, saved sets, playlist saving and a More like this action. Playback uses the existing single session. AI responses can select only supplied catalog IDs; errors/quota limits never simulate a successful AI session. Private listening excludes recent history from DJ input. The Firebase JavaScript SDK is loaded only when AI is requested. No paid billing was enabled.

## Compilation and delivery evidence

Both web interfaces and native APKs are compiled during packaging. No automated tests, screenshots or playback/UI/AI runtime checks were run, honoring the owner's explicit testing limit. Installation and publication outcomes are recorded in PROGRESS.md. The owner's prior screenshot/Spotify review was authorized separately.

## Service and device dependencies

Firebase AI Logic was enabled by the owner and its Gemini Developer backend is configured in the app; an actual model request has not been verified. Availability depends on the project's enabled service, model access, quota and any App Check/key restrictions. Narration depends on installed offline voices; Kiswahili is not guaranteed on every device. Artwork and genre coverage depend on source metadata. Neither visual parity nor interruption-free playback is claimed without device verification.
